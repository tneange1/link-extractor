# Link Extractor для Remnawave

Добавляет в подписки Remnawave ключи со сторонних серверов, панелей и провайдеров без ботов и ручной работы.

Вставляете ключи `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://`, `tuic://` или ссылку на подписку, а экстрактор:

- расшифровывает ключи и подписки, включая base64, Xray JSON, sing-box JSON и Clash/Mihomo YAML;
- создаёт в панели **внутренний сквад** и **хосты** с тегом из названия;
- выдаёт ключи только юзерам из этого сквада, в любом формате клиента (base64, Clash/Mihomo, sing-box, Xray JSON для Happ/v2rayNG);
- собирает ключи в **группы по странам**: одна точка входа «🇺🇸 США» с автовыбором по пингу и общий автовыбор «⚡ Авто · все страны», а сами ключи становятся скрытыми хостами;
- сам обновляет подписки-источники по таймеру;
- шлёт **уведомления в Telegram**: новые и пропавшие ключи, ошибки подписок, обновления;
- **обновляется сам** с GitHub без захода на сервер;
- делает **бэкапы** своих данных и присылает их в Telegram;
- **обновляет себя и панель Remnawave** по кнопке в боте (себя — ещё и автоматически);
- управляется **Telegram-ботом**: несколько панелей в одном боте, всё то же, что на веб-странице, и **установка на новые серверы прямо из бота** по SSH;
- добавляет пункт «Экстрактор ссылок» в меню панели.

## Как это работает

```
клиент → reverse proxy → link-extractor → remnawave-subscription-page → Remnawave
                              │
                              └─ подменяет хосты-заглушки на настоящие ключи
```

1. На каждый ключ в Remnawave создаётся **скрытый** хост на **инбаунде-заглушке**: профиль без нод, например `Balancer`. Адрес хоста имеет вид `server.le-xxxxxxxx`, тег хоста берётся из названия.
2. Хост закрыт сквадом источника (`ALLOW_ONLY`), поэтому Remnawave сам решает, кому его отдать. Вкл/выкл, порядок и название хоста настраиваются прямо в панели.
3. На каждую страну создаётся **видимый** хост-группа (`🇺🇸 США`, тег `AUTO`), плюс общий хост `⚡ Авто · все страны`.
4. Экстрактор стоит перед страницей подписки и находит в ответе заглушки `.le-xxxxxxxx`:
   - **хост-группу** превращает в автовыбор из ключей этой страны, доступных юзеру;
   - **хост-ключ** (если группы выключены) заменяет настоящим ключом.

## Требования

- Remnawave **2.x** и `remnawave-subscription-page` в docker-сети `remnawave-network`
- Docker и Docker Compose
- API-токен Remnawave: *Настройки Remnawave → API-токены*
- Профиль конфигурации **без нод** с одним любым инбаундом, например профиль `Balancer` с инбаундом `VM`. Это заглушка: юзеры на неё никуда не подключаются. Если такого профиля нет, создайте его и не назначайте ни на одну ноду.

## Установка

### Одной командой (рекомендуется)

На сервере с панелью Remnawave, от root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/tneange1/link-extractor/main/install.sh)
```

Установщик спросит, что ставить:

| Вариант | Что будет |
|---|---|
| **1. Экстрактор** | экстрактор на этот сервер с панелью |
| **2. Telegram-бот** | только бот (можно на отдельный сервер без панели) |
| **3. Экстрактор + бот** | всё на этот сервер с панелью |

Что делает установщик:

- ставит Docker и git, если их нет;
- скачивает проект в `/opt/link-extractor`;
- спрашивает API-токен Remnawave, сам находит домены панели и подписки и проверяет, что у токена хватает прав;
- сам настраивает **Caddy** или **nginx**: сохраняет копию конфига, проверяет новый и при ошибке откатывает;
- включает автообновление и бэкапы;
- в конце показывает пароль страницы и `API_TOKEN` для бота.

Повторный запуск безопасен: настройки в `.env` сохраняются, уже настроенный прокси не трогается.

### Вручную

```bash
cd /opt && git clone https://github.com/tneange1/link-extractor && cd link-extractor
cp .env.example .env
mkdir -p data/bot && chown -R 1000:1000 data
nano .env      # COMPOSE_PROFILES, TG_BOT_TOKEN, TG_ADMIN_IDS
docker compose up -d --build
# пароль страницы и API-токен (они в базе):
docker exec link-extractor node -e 'console.log(require("/app/data/store.json").secrets)'
```

### `.env` — только три строки

```env
COMPOSE_PROFILES=extractor,bot   # что запускать: extractor | bot | extractor,bot
TG_BOT_TOKEN=123456:ABC...       # токен бота от @BotFather
TG_ADMIN_IDS=6711082810          # id админов через запятую
```

**Всё остальное хранится в базе** (`data/store.json` у экстрактора, `data/bot/db.json` у бота), настраивается в боте (*⚙️ Настройки*) или на странице экстрактора и попадает в бэкапы:

| Где | Что |
|---|---|
| база экстрактора | пароль страницы, API-токен для бота, токен Remnawave, название и домен панели, куда слать уведомления, автообновление экстрактора и Remnawave, интервалы обновления и бэкапов, инбаунд-заглушка, группы, источники и ключи |
| база бота | список панелей с их токенами, интервал автобэкапа бота |

Если на сервере старый `.env` со всеми переменными, повторный запуск установщика сам перенесёт значения в базу и оставит в `.env` только эти три строки. Старый файл он сохранит рядом как `.env.bak-*`.

## Reverse proxy

Нужно сделать две вещи:

1. **Домен подписки** направить в `link-extractor:3020` вместо `remnawave-subscription-page:3010`.
2. **Домен панели:** путь `/link-extractor/` направить в экстрактор и вставить в страницу панели скрипт пункта меню.

### Caddy

Стоковый Caddy не умеет менять HTML. Поэтому HTML-страницы панели отдаёт сам экстрактор: в `.env` укажите `PANEL_DOMAIN=panel.example.com`.

```caddy
https://panel.example.com {
        @extractor path /link-extractor /link-extractor/*
        handle @extractor {
                reverse_proxy link-extractor:3020
        }
        @html header Accept *text/html*
        handle @html {
                reverse_proxy link-extractor:3020
        }
        handle {
                reverse_proxy * http://remnawave:3000
        }
}

https://sub.example.com {
        reverse_proxy * http://link-extractor:3020
}
```

```bash
cd /opt/remnawave/caddy
docker compose exec caddy caddy validate --config /etc/caddy/Caddyfile && docker compose restart caddy
```

### Nginx

Nginx умеет вставлять скрипт сам (`sub_filter`), поэтому `PANEL_DOMAIN` не нужен.

**Если nginx в docker-сети `remnawave-network`:**

```nginx
# Панель
server {
    server_name panel.example.com;
    # ... ваши listen / ssl / прочие настройки ...

    location /link-extractor/ {
        proxy_pass http://link-extractor:3020;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://remnawave:3000;
        # ... ваши proxy_set_header ...

        # пункт «Экстрактор ссылок» в меню
        proxy_set_header Accept-Encoding "";
        sub_filter '</head>' '<script src="/link-extractor/inject.js" defer></script></head>';
        sub_filter_once on;
        sub_filter_types text/html;
    }
}

# Подписка
server {
    server_name sub.example.com;
    # ... ваши listen / ssl ...

    location / {
        proxy_pass http://link-extractor:3020;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

**Если nginx работает на хосте или в `network_mode: host`** (например, установлен скриптом eGames):

1. Пробросьте порт в `docker-compose.yml` экстрактора. Если 3020 занят, возьмите любой свободный:
   ```yaml
       ports:
         - "127.0.0.1:3020:3020"
   ```
2. В конфиге выше замените `link-extractor:3020` → `127.0.0.1:3020`, а `remnawave:3000` → `127.0.0.1:3000`. Если у вас есть `upstream`-блоки, просто поменяйте адрес в upstream подписки.
3. Найти нужные места в конфиге можно так:
   ```bash
   grep -rn "3010\|subscription-page" /opt/remnawave/nginx.conf
   ```

Проверка и перезапуск:

```bash
docker exec remnawave-nginx nginx -t && docker exec remnawave-nginx nginx -s reload
# или для nginx на хосте:
nginx -t && systemctl reload nginx
```

## Использование

Откройте `https://panel.example.com/link-extractor/` или пункт **«Экстрактор ссылок»** в меню панели (Ctrl+F5 после настройки прокси) и войдите с `ADMIN_PASSWORD`. На домене подписки страница перенаправляет на домен панели, там остаётся только API для бота.

### Добавление ключей

1. Вставьте в поле ключи и/или ссылки на подписки, по одной на строку. Подойдёт и целиком вставленный Xray/sing-box JSON или Clash YAML.
2. **Название.** Из него получается имя сквада (`My VPN` → `MY VPN`) и тег хостов (`MY_VPN`). Кириллица переводится в латиницу.
3. **User-Agent** для загрузки подписки:
   - **Авто** перебирает Happ Android → Happ iOS → INCY → v2rayNG → Happ Windows до первого, на котором подписка отдала настоящие ключи. Заглушки вида `127.0.0.1` отбрасываются.
   - **Пресеты** Happ / INCY / v2rayNG / v2rayN. Для Happ и INCY отправляются заголовки устройства с постоянным HWID: у провайдера это займёт одно устройство.
   - **Свой** — любая строка.
4. **Кому выдавать:**
   - *Создать сквад из названия* (по умолчанию) — новый сквад с инбаундом-заглушкой;
   - *существующий сквад* — в него добавится инбаунд-заглушка;
   - *Всем пользователям* — хосты без ограничения по сквадам.
5. **«Расшифровать»** показывает, что будет добавлено. **«Добавить»** сохраняет источник и создаёт сквад и хосты.
6. Добавьте нужных юзеров в созданный сквад: *Внутренние сквады → сквад → юзеры*. Юзер может состоять в нескольких сквадах одновременно.

### Управление

- **В панели, раздел «Хосты»:** переименовать, выключить, удалить, поменять порядок или тег. **Адрес и порт хостов `*.le-xxxxxxxx` не меняйте**: по ним экстрактор находит ключ. Удалённый в панели хост не пересоздаётся.
- **В экстракторе:**
  - вкл/выкл источник целиком или отдельные ключи;
  - сменить сквад или User-Agent;
  - обновить подписку вручную;
  - удалить источник: его хосты удалятся, сквад — по желанию.
- **Подписки-источники** обновляются каждые `REFRESH_MINUTES` минут. Новые ключи становятся новыми хостами, хосты исчезнувших ключей удаляются. Если провайдер недоступен, остаются последние полученные ключи.
- **Инбаунд-заглушка** выбирается автоматически (профиль `Balancer` или любой профиль без нод). Сменить её можно в блоке «Источники».

### Группы стран (автовыбор)

Включены по умолчанию (блок **«Группы стран»** на странице экстрактора).

- Страна ключа определяется по флагу в названии (`🇺🇸`), а без флага — по словам «США», «USA», «Польша», «Poland» и т.п. Ключи без страны попадают в группу `🌐 Другие`.
- В панели на каждую страну появляется один видимый хост с тегом `AUTO`, плюс общий `⚡ Авто · все страны`. Название общего автовыбора можно поменять. Порядок групп меняется перетаскиванием в «Хостах».
- Ключи становятся **скрытыми** хостами со своим тегом. Выключенный в панели ключ выпадает из автовыбора.
- Юзер получает в группе только ключи тех источников, в чьих сквадах он состоит.

Что видит клиент:

| Клиент / формат | Группа страны | «Все страны» |
|---|---|---|
| Happ, v2rayNG JSON (Xray JSON) | один сервер с балансером `leastPing` | один сервер с балансером |
| Clash / Mihomo | группа `url-test` | группа `url-test` |
| sing-box / Hiddify | `urltest` | `urltest` |
| base64 / обычный список | ключи по отдельности: «🇺🇸 США 1», «🇺🇸 США 2»… (автовыбора в этом формате нет) | не показывается |

Если выключить группы, ключи снова станут обычными видимыми хостами, а хосты групп удалятся.

### Telegram-уведомления

1. Создайте бота у [@BotFather](https://t.me/BotFather) и возьмите токен.
2. Напишите боту `/start` (или добавьте его в группу) и узнайте chat id, например через [@userinfobot](https://t.me/userinfobot).
3. Впишите в `.env` `TG_BOT_TOKEN` и `TG_CHAT_ID`, затем выполните `docker compose up -d`.
4. На странице экстрактора нажмите **«Отправить тест»**.

Приходят сообщения о новых и пропавших ключах в подписках-источниках, об ошибке и восстановлении подписки, о добавлении источника и об автообновлении (успех или откат).

### Проверка подписки юзера

Блок **«Проверка подписки юзера»**: вставьте ссылку подписки юзера и выберите клиента. Экстрактор покажет:

- статус юзера и его сквады;
- формат ответа;
- сколько хостов-заглушек подменено;
- почему ключи не добавились, если не добавились.

Из консоли то же самое видно по заголовку `X-Link-Extractor`:

```bash
curl -sI -A "v2rayNG/1.10" https://sub.example.com/<shortUuid> | grep -i x-link
# x-link-extractor: base64;+3
```

## Telegram-бот

Бот управляет одной или несколькими панелями. Для каждой панели в нём есть то же, что на веб-странице экстрактора:

- **📥 Добавить ключи** — прислать ключи, ссылки на подписки или .txt-файл. Бот покажет найденное, спросит название и кому выдавать: новый сквад, существующий или всем.
- **📚 Источники** — включить или выключить источник, обновить его, сменить сквад или User-Agent, включать и выключать отдельные ключи, удалить источник (вместе со сквадом или без).
- **🌍 Группы** — включить или выключить группы стран, переименовать общий автовыбор.
- **🔎 Проверить подписку** — что получит конкретный юзер в конкретном клиенте.
- **💾 Бэкапы** — сделать бэкап и получить файл, скачать любой из последних, восстановить из файла.
- **💾 Бэкап бота** (на главном экране) — один файл: список панелей с токенами, настройки бота и свежие данные всех панелей. Делается сам раз в сутки (интервал настраивается), восстанавливается из файла целиком или только списком панелей.
- **⚙️ Настройки** — токен Remnawave, домен панели, пароль страницы (посмотреть или сменить), автообновление экстрактора и Remnawave, интервал бэкапов, интервал обновления подписок, инбаунд-заглушка, **куда слать уведомления**, тестовое уведомление.

### Уведомления каждой панели — в свой чат или топик

1. Добавьте бота в группу. Если нужны топики, включите в группе «Темы».
2. В нужном топике отправьте `/bind`.
3. Нажмите панель, которую туда привязать, или «Все панели».

После этого уведомления этой панели (новые и пропавшие ключи, ошибки, бэкапы, обновления) приходят в выбранный топик, и туда же сразу придёт тестовое сообщение. Вернуть уведомления в личку можно так: *⚙️ Настройки → 🔔 Куда слать уведомления → Слать мне в личку*.
- **⬆️ Обновить экстрактор / Remnawave** — проверить GitHub и обновиться сейчас; скачать новые образы панели и перезапустить её.

Бот отвечает только админам из `TG_ADMIN_IDS` и только в личке. Свой id можно узнать командой `/id`.

### Несколько панелей

- **Добавить ключи сразу в несколько панелей.** *📥 Добавить ключи* → название → бот спросит, **в какие панели добавить** (галочки или «Во все панели»). На каждой панели создаётся свой сквад и свои хосты.
- **Один источник на всех панелях.** В карточке источника есть кнопка *🌐 На всех панелях*. Она показывает, где этот источник есть, и умеет:
  - включить или выключить его везде;
  - обновить везде;
  - **добавить в панели, где его нет**;
  - удалить везде (вместе со сквадами или без).

На главном экране бота есть список панелей. Добавить панель можно двумя способами:

- **➕ Добавить панель** — если экстрактор уже стоит на сервере. Нужны адрес (обычно домен подписки, например `sub.example.com`) и `API_TOKEN` из `/opt/link-extractor/.env` на том сервере.
- **🛠 Установить на сервер** — бот сам поставит экстрактор (см. ниже).

Если бот и экстрактор стоят на одном сервере, эта панель добавляется в бота автоматически.

### Установка на сервер из бота

1. Нажмите **🛠 Установить на сервер**.
2. Пришлите IP и порт SSH, выберите пользователя (обычно `root`) и способ входа:
   - **пароль**;
   - **приватный ключ** — текстом или файлом; если ключ зашифрован, бот спросит пароль от него.
3. Бот подключится, проверит сервер и покажет:
   - отпечаток SSH-ключа сервера;
   - есть ли Docker и панель Remnawave;
   - какой стоит прокси (Caddy или nginx) и домен подписки;
   - найден ли API-токен Remnawave.
4. Отметьте нужное: авто-настройку Caddy/nginx и автообновление. Задайте название. Укажите API-токен Remnawave (*Настройки Remnawave → API-токены*).
5. Нажмите **🚀 Установить**. Лог установки будет виден прямо в сообщении. В конце панель сама появится в боте, а уведомления этого сервера начнут приходить в этот же чат.

> 🔒 **Безопасность.** Сообщения с паролем, ключом и токенами бот сразу удаляет из чата. Данные входа на сервер нигде не сохраняются: они живут в памяти только во время установки. Хранятся только адрес экстрактора и его `API_TOKEN`, в `data/bot/panels.json` с правами 600. Если присылали пароль root, после установки лучше его сменить. Пользователь, если не root, должен иметь `sudo` без пароля.

## Бэкапы

Бэкапятся **данные экстрактора** (`store-*.json`):
- источники: ссылки на подписки и ключи, названия, User-Agent, выключенные ключи;
- какие сквады и хосты в панели принадлежат какому источнику, группы стран;
- настройки и секреты: пароль страницы, API-токен, токен Remnawave, название, домен, интервалы, заглушка, группы, уведомления.

БД самой панели в бэкап **не входит**: ни юзеры, ни их подписки, ни твои собственные хосты. При восстановлении пароль, API-токен и токен Remnawave остаются текущими, если они уже заданы, чтобы бот не потерял доступ к панели.

> 🔒 В бэкапах есть токены и пароли — не пересылайте их.

При восстановлении экстрактор сам пересоздаёт в панели свои хосты и группы. Если какого-то сквада больше нет, он создаётся заново с тем же названием, но юзеров в него нужно добавить снова. Бэкап делается раз в `BACKUP_INTERVAL_HOURS`, по кнопке в боте или на странице. Файл кладётся в `data/backups/` и приходит в Telegram. Хранится `BACKUP_KEEP` последних.

**Восстановление:** в боте *💾 Бэкапы → ♻️ Восстановить из файла* и прислать `store-….json`. Перед восстановлением текущее состояние сохраняется отдельным бэкапом. Хосты, сквады и группы в панели после этого синхронизируются автоматически.

## Обновление

Контейнер `link-extractor-updater` раз в `UPDATE_INTERVAL_MINUTES` минут проверяет GitHub. В боте кнопка **⬆️ Обновить экстрактор** проверяет сразу. Если есть новый коммит, он делает `git reset --hard`, пересобирает `link-extractor` и пишет в Telegram. Если сборка упала, откатывается на прошлую версию. `.env` и `data/` не трогаются.

Логи автообновления:

```bash
docker logs -f link-extractor-updater
```

**Панель Remnawave:** кнопка **⬆️ Обновить Remnawave** в боте или на странице. Она выполняет `docker compose pull` и `docker compose up -d` в `REMNAWAVE_DIR`, а в Telegram приходит результат: обновлено, уже последняя версия или ошибка. Автоматически это происходит, только если включить `REMNAWAVE_AUTO_UPDATE=true`.

Обновить экстрактор вручную:

```bash
cd /opt/link-extractor && git pull && docker compose up -d --build
```

> Апдейтеру нужен доступ к `/var/run/docker.sock`, чтобы пересобирать контейнер. Если не хотите этого, поставьте `AUTO_UPDATE=false` или удалите сервис `updater` из `docker-compose.yml`.

## Резервная копия

Все данные лежат в `data/store.json`: источники, ключи, связи с хостами и сквадами.

```bash
cp /opt/link-extractor/data/store.json ~/link-extractor-backup.json
```

## Удаление

1. Удалите источники на странице экстрактора: их хосты удалятся из панели.
2. Верните в reverse proxy адрес `remnawave-subscription-page:3010` для домена подписки и уберите блоки экстрактора.
3. Остановите контейнер:
   ```bash
   cd /opt/link-extractor && docker compose down
   ```

## Ограничения

- **Страница подписки в браузере** показывает заглушки `…le-xxxxxxxx`. VPN-клиенты получают настоящие ключи.
- **Hysteria2 в Xray JSON** выдаётся через `protocol: "hysteria"` (нужен свежий Xray-core у клиента). Hysteria2 с `obfs`/port hopping в Xray JSON не выдаётся. В base64, Clash и sing-box выдаются все ключи.
- **xhttp в sing-box** не поддерживается: такие ключи в sing-box-подписку не попадут.
- **Трафик и лимиты** по сторонним ключам Remnawave не считает: их считает сервер-источник.
